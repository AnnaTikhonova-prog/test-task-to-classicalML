# Avito Bot Detection

Решение задачи определения автоматизированного трафика: для каждой `cookie_id` из теста вычисляется score в [0, 1]. Метрика: Precision при Recall ≥ 70% (`metric.py`).

**Результат на скрытом тесте: 0,823** (валидационная оценка: 0,7566, 95% CI [0,68; 0,84] на фолде формы теста).

Подход: 347 поведенческих признаков, построенных по событиям внутри индивидуального суточного окна куки, и одиночный CatBoost (SqrtBalanced), усреднённый по семи сидам. Подробности: [REPORT.md](REPORT.md).

## Требования

- Python 3.12.4
- Зависимости: [requirements.txt](requirements.txt) (pandas, NumPy, scikit-learn, CatBoost, LightGBM, SciPy; версии зафиксированы)
- Данные в каталоге `data/`: `train.csv`, `test.csv`, `events.csv.gz`

## Установка

```bash
python -m pip install -r requirements.txt
```

## Быстрый старт

```bash
python run.py
```

Команда выполняет полный цикл: построение признаков, валидацию (SELECT → EXAM → HORIZON), финальное обучение и запись `submission.csv`. Время работы: от 1 до 1,5 часов на 22-ядерном CPU.

### Опции

```bash
python run.py --data-dir data --output submission.csv   # пути по умолчанию
python run.py --skip-validation                         # сабмит по зафиксированной конфигурации, без валидации (~5 мин)
python run.py --features-cache cache.pkl                # кэш матрицы признаков (удалить при изменении src/features.py)
```

### Проверка файла отправки

```bash
python check_submission.py
```

Проверяет контракт файла и сообщает число совпадающих score (метрика обрабатывает совпадения как одну группу).

## Валидация

Случайные фолды для временной задачи не используются. Схема состоит из трёх частей:

1. **SELECT**: два фолда с расширяющимся окном обучения. Все решения принимаются только здесь: веса классов для каждой модели, набор признаков, выбор кандидата.
2. **EXAM**: нетронутый блок 17.04 по 19.04. Итоговая оценка замороженного рецепта с разбросом по сидам и бутстрап-интервалом.
3. **HORIZON**: семь дней обучения, семь дней предсказания. Фолд формы реального теста.

Все кандидаты сравниваются как мешки из пяти сидов; файл отправки использует семь сидов. Подробности и таблицы: [REPORT.md](REPORT.md).

## Воспроизводимость

- Все сиды и границы фолдов зафиксированы в `src/config.py`.
- Повторный запуск воспроизводит идентичный `submission.csv` (проверено побайтовым сравнением хэшей).
- Прогон выполнялся в чистом изолированном окружении, собранном из `requirements.txt`.

## Соответствие правилам

Внешние API и большие языковые модели не используются. Тестовая выборка не размечалась вручную. Правила, привязанные к конкретным `cookie_id`, отсутствуют. Признаки не используют события вне окна куки (проверяется тестом `extras/test_window_leakage.py`).
