# Отчёт по решению задачи определения автоматизированного трафика

## Аннотация

В настоящей работе рассматривается задача бинарной классификации кук на классы «бот» и «человек» с метрикой качества Precision при Recall ≥ 70%. Итоговое решение состоит из 347 поведенческих признаков, построенных по событиям внутри индивидуального суточного окна куки, и одиночной модели CatBoost с весами классов SqrtBalanced, усреднённой по семи сидам. Согласно построенной мною схеме валидации, ожидаемое качество на тестовой выборке составляет ≈ 0,76 P@R70 (фолд формы теста «7 дней обучения, 7 дней предсказания»), 95% доверительный интервал [0,68; 0,84]; на нетронутом трёхдневном блоке получено значение 0,7533. Фактический результат на скрытой тестовой выборке составил 0,823, что находится в пределах указанного интервала.

## 1. Постановка задачи

Единицей классификации является одна запись `cookie_id`. Для каждой тестовой куки необходимо получить оценку из отрезка [0, 1]; качество оценивается официальной метрикой из `metric.py`, то есть максимальным значением precision при условии recall ≥ 0,70. Существенная деталь метрики: куки с одинаковым значением score обрабатываются как одна группа, поэтому наличие массовых совпадений score способно изменить итоговое значение метрики. Данное свойство учитывалось мною при подготовке файла отправки и контролируется отдельным скриптом `check_submission.py`. Калибровка итогового score не выполнялась, поскольку метрика использует только ранжирование.

## 2. Данные и разведочный анализ

Обучающая выборка содержит 11 091 куку (899 положительных примеров, доля класса 8,1%) за период с 6 по 19 апреля 2026 года; тестовая выборка содержит 4 909 кук за период с 20 по 26 апреля. Журнал событий содержит 328 905 записей. В ходе разведочного анализа (скрипт `extras/inspect_data.py`) мною были выявлены следующие особенности данных:

1. **Индивидуальные окна наблюдения.** Каждая кука снабжена собственным 24-часовым окном `[window_start_ts, window_end_ts)`. Признаки строятся исключительно по событиям внутри окна: события за его пределами относятся к другому периоду, а часть из них является следствием реакции антифрод-системы. Корректность фильтрации подтверждена тестом `extras/test_window_leakage.py`: добавление 1200 синтетических событий до начала и после конца окна не изменило ни одного признака.
2. **Событие captcha_shown как следствие блокировки.** Журнал содержит 7 928 событий `captcha_shown`, все они происходят после `window_end_ts`. Использование данного события в качестве признака означало бы подглядывание в будущее; благодаря фильтрации по окну оно в признаки не попадает.
3. **Дубликаты событий.** В журнале присутствуют 4 863 полных дубликата строк (предположительно артефакт логирования). Данные строки завышают счётчики событий, не неся дополнительной информации, и удаляются при загрузке (`src/train.py`). Записи с совпадающими `(cookie_id, event_ts, event_name)`, но различающимся содержимым (407 строк), были сохранены как легитимные.
4. **Несогласованный регистр поля platform.** В исходных данных встречаются 11 вариантов записи (`WEB`, `Web`, `web`, `ANDROID` и другие); перед агрегацией значения приводятся к нижнему регистру.
5. **Пропуски.** Пропуск в записи события интерпретируется как отсутствие наблюдения; после агрегации по куке соответствующие признаки заполняются нулём. Необработанные строки User-Agent в модель не передаются: используются только локально извлечённые маркеры (признаки headless, семейство браузера, операционная система, версия) и доля пропусков.

## 3. Признаки

Для каждой куки строится 347 признаков (реализация: `src/features.py`). Основные группы признаков:

- счётчики и доли типов событий, значений `eid`, платформ, категорий, локаций и продавцов;
- показатели разнообразия сущностей: количества уникальных значений и энтропии распределений;
- статистики межсобытийных интервалов (медианы, квантили, доли нулевых и субсекундных интервалов) и темпа событий;
- характеристики сессий с границей неактивности 30 минут: количество, размеры и длительности;
- распределение активности по часам суток;
- характеристики траектории курсора: длина пути, скорость между наблюдаемыми точками, количество смен направления;
- переходы между соседними событиями и навигация по страницам поисковой выдачи.

Дополнительно реализованы 43 экспериментальных признака (регулярность интервалов, конфликты User-Agent и платформы и другие); они сохранены в коде для воспроизводимого сравнения, однако в итоговую модель не включены (см. раздел 8).

## 4. Схема валидации

Поскольку тестовый период следует непосредственно за обучающим и длится семь дней, случайное разбиение на фолды является некорректным: оно перемешивает время и приводит к завышенным оценкам. В связи с этим мною была построена вложенная хронологическая схема валидации:

- **SELECT**: два фолда с расширяющимся окном обучения (train ≤ 10.04 → val 11.04 по 13.04; train ≤ 13.04 → val 14.04 по 16.04). Все решения принимались исключительно на данных фолдах: схема весов классов для каждой модели, набор признаков, выбор итогового кандидата.
- **EXAM**: train ≤ 16.04 → val 17.04 по 19.04 (1 951 кука, 160 положительных примеров). Полностью нетронутый блок, на котором замороженный рецепт получает итоговую оценку с разбросом по сидам и бутстрап-интервалом; дополнительно формируется таблица всех кандидатов для оценки стабильности отбора.
- **HORIZON**: train ≤ 12.04 → predict 13.04 по 19.04 (5 161 кука, 408 положительных примеров). Единственный фолд, повторяющий форму реального теста (семь дней обучения, семь дней предсказания); его оценка рассматривается как репрезентативная для тестовой выборки.

Отдельно следует отметить два методологических решения. Во-первых, все кандидаты сравнивались в форме мешков из пяти сидов (в файле отправки используется семь сидов): разброс одной и той же модели между сидами достигает ±2 п.п., вследствие чего сравнение одиночных запусков не является информативным. Во-вторых, стекинг обучался на out-of-fold предсказаниях временных под-фолдов, при этом мета-модель для каждого оцениваемого блока обучалась строго на более ранних днях. Ручные веса в блендах не подбирались: рецепт 0,75/0,25 из первой версии решения участвовал в сравнении в качестве рядового кандидата.

## 5. Модели и процедура отбора

В сравнение были включены пять базовых моделей (`ExtraTrees`, `RandomForest`, `HistGradientBoosting`, `CatBoost`, `LightGBM`), шесть детерминированных блендов вероятностей и рангов, а также два варианта OOF-стекинга (логистическая регрессия и неотрицательный метод наименьших квадратов). Схема взвешивания классов подбиралась отдельно для каждой модели на фолдах SELECT, поскольку экспериментально установлено отсутствие универсальной схемы:

| Модель | Выбранная схема | Альтернативы |
|---|---|---|
| ExtraTrees | balanced (0,5916) | без весов 0,5215 |
| RandomForest | balanced_subsample (0,6382) | balanced 0,6114; без весов 0,5218 |
| HistGB | без весов (0,6843) | balanced 0,6834 |
| CatBoost | SqrtBalanced (0,7032) | Balanced 0,6826; без весов 0,6718 |
| LightGBM | full ratio (0,7105) | sqrt 0,6890; без весов 0,6877 |

Также проверялось сокращение набора признаков: полный набор дал 0,7103, а топ-60 по важности ExtraTrees (важности усреднены по сидам и вычислены только на обучающей части фолда) дал 0,6829. Сокращение набора было отклонено.

Полный прогон пайплайна занимает примерно от 1 до 1,5 часов на 22-ядерном процессоре: построение признаков занимает около одной минуты, основные затраты связаны с мешками сидов и OOF-под-фолдами.

## 7. Анализ ошибок

Анализ ошибок выполнен на блоке EXAM в рабочей точке recall = 0,70. При пороге 0,4124 получены значения: TP = 113, FN = 47, FP = 37, TN = 1754 (precision = 0,7533). Медианы признаков по группам:

| Признак | TP | FN | FP | TN |
|---|---:|---:|---:|---:|
| n_events | 21 | 11 | 22 | 12 |
| events_per_active_span_hour | 9,6 | 5,9 | 10,3 | 6,1 |
| gap_sec_median | 20,5 | 38,0 | 26,0 | 58,0 |
| item_id_nunique | 12 | 6 | 11 | 6 |
| search_query_nunique | 5 | 2 | 5 | 3 |

Структура ошибок устойчива между блоками. Пропущенные боты (FN) практически неотличимы от обычных пользователей с низкой активностью (TN): небольшое число событий, низкий темп, малое разнообразие объявлений. Ложные срабатывания (FP) соответствуют гиперактивным реальным пользователям, чья активность превосходит активность выявленных ботов. Таким образом, дальнейшее повышение качества ограничено принципиальной отделимостью «тихих» ботов от «тихих» пользователей в имеющихся данных, а не настройкой параметров модели.

## 8. Отрицательные результаты

В ходе работы был получен ряд отрицательных результатов (все значения вычислены на одних и тех же фолдах):

- **43 экспериментальных признака** (регулярность интервалов, энтропия часов, характеристики сессий, конфликты User-Agent и платформы и другие): CatBoost 0,7231 против 0,7419 на основном наборе; HistGB +0,0013, что находится в пределах шума. В модель не включены.
- **Сокращение набора до 60 признаков:** 0,6829 против 0,7103 у полного набора. Отклонено.
- **TF-IDF по User-Agent и поисковым запросам:** существенно уступает поведенческой модели (проверено в первой версии решения). Не включено.
- **Категориальные моды платформы, категории, локации и браузера:** 0,7352 против 0,7419 у базового CatBoost. Не включены.
- **Ручные веса бленда (0,75/0,25):** на SELECT уступают как одиночному CatBoost, так и OOF-стекингу. Заменены формальной процедурой сравнения кандидатов.
- **OOF-стекинг (логистическая регрессия и NNLS):** не продемонстрировал устойчивого преимущества над одиночным CatBoost (0,7202 против 0,7233 на SELECT). Оставлен в списке кандидатов, но не выбран.

## 9. Ограничения и возможные направления

- Валидация охватывает 14 дней и 899 положительных примеров; блоки содержат от 160 до 408 положительных примеров, что обусловливает широкие доверительные интервалы шириной от 7 до 9 п.п. Различия между ведущими кандидатами (около 0,5 п.п.) находятся ниже уровня шума отбора, в связи с чем выбор был зафиксирован протоколом заранее.
- Обучающий и тестовый периоды относятся к одному короткому интервалу апреля; переносимость решения на другие периоды не проверялась.
- Возможные направления дальнейшей работы (гипотезы, не проверявшиеся в настоящей работе): признаки на основе методов обнаружения аномалий (Isolation Forest, LOF), кластерные признаки, триграммы последовательностей событий, систематический подбор гиперпараметров с целевой метрикой.

## 10. Воспроизводимость

### Требования

- Python 3.12.4
- Зависимости из `requirements.txt`: pandas, NumPy, scikit-learn, CatBoost, LightGBM, SciPy (точные версии зафиксированы)

### Установка и запуск

```bash
python -m pip install -r requirements.txt
python run.py
```

Команда `python run.py` выполняет полный цикл: построение признаков, валидацию по схеме SELECT → EXAM → HORIZON, финальное обучение выбранного рецепта и запись `submission.csv`.

### Проверка файла отправки

```bash
python check_submission.py
```

### Гарантии воспроизводимости

- Все источники случайности (сиды моделей, сид бутстрапа) и границы временных блоков зафиксированы в `src/config.py`.
- Повторный запуск воспроизводит идентичный `submission.csv` (проверено побайтовым сравнением хэшей).
- Прогон выполнялся в чистом изолированном окружении, собранном исключительно из `requirements.txt`.
- Итоговый файл содержит 4 909 строк; все значения score уникальны (совпадения отсутствуют).
- Полный журнал прогона: `extras/run_log.txt`.

Внешние API и большие языковые модели не использовались. Тестовая выборка не размечалась вручную. Правила, привязанные к конкретным `cookie_id`, отсутствуют. Признаки не используют события вне окна куки, что подтверждается тестом `extras/test_window_leakage.py`.
